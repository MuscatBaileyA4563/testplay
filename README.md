# ブロック崩しde足トレ

カメラの前で足踏み・ひざ上げをすると、その動きでバーが左右に動くブロック崩しです。
運動療法の自主トレーニングを想定し、運動時間とポイントが自動で記録されます。

ビルド不要の静的ファイル一式です。下記6ファイルを同じフォルダに置いて配信すればそのまま動きます
（すべて相対パス構成のため、GitHub Pages のサブディレクトリ配信でも設定変更は不要です）。

```
index.html              本体（ゲーム・音・描画・記録のすべて）
sw.js                   Service Worker（オフライン起動用）
manifest.webmanifest    PWA の定義
icon-192.png / icon-512.png / icon-maskable.png
```

---

## 動かす

### 公開する

HTTPS で配信してください。カメラ（getUserMedia）と Service Worker は
**セキュアコンテキスト（https または localhost）でしか動きません。**
GitHub Pages、社内の HTTPS サーバ、いずれでも構いません。

### 手元で確認する

```bash
python3 -m http.server 8080
# → http://localhost:8080 をブラウザで開く
```

`index.html` をダブルクリックして `file://` で開くと、Service Worker もカメラも動きません。
必ずローカルサーバ経由で開いてください。

### ポート開放について

**不要です。** 上記のローカルサーバは自分のPCの中だけで完結するので、
ルータのポート開放（ポートフォワーディング）やファイアウォールの穴あけは必要ありません。

同じLANの他端末（スマホなど）から `http://192.168.x.x:8080` で開くこともできますが、
**その場合はカメラが使えません。** http はセキュアコンテキストではないため、ブラウザが
getUserMedia をブロックします。スマホでの実機確認は、次のいずれかで行ってください。

- HTTPS のホスティング（GitHub Pages など）に置いて、その URL を開く
- 開発用トンネル（`cloudflared tunnel` や `ngrok http 8080` 等）で HTTPS の URL を借りる
- Android の場合のみ、Chrome の `chrome://flags/#unsafely-treat-insecure-origin-as-secure`
  に LAN の URL を登録する（検証目的の一時的な手段）

いずれもインターネット側からPCへ着信させる構成ではないので、ポート開放はしません。

## 操作と画面

- カメラ映像の**下部およそ30%**の範囲で、フレーム間の動きを検出します。動きの重心が左に寄ればバーが左へ、
  右に寄れば右へ動きます。立位でのひざ上げでも、座位での足踏みでも操作できます。
- カメラが使えない場合は矢印キーと画面タッチでも動きます（動作確認用）。
- 画面下のバーは**運動強度メーター**で、検出した動きの量を表示します。
- 右下にツールバー（音／速さ／カメラ切替／中断）と、選択中の速さの表示があります。

## ボールの速さ

| 表記 | 表示倍率 | 位置づけ |
| --- | --- | --- |
| L | ×0.77 | ゆっくり |
| N | ×1.00 | 基準（初期値） |
| H | ×1.25 | 速い |

メニューの設定と、プレイ中のツールバーのボタン（カメラ切替の隣）のどちらからでも変更できます。
飛んでいる最中のボールも、方向はそのままに速度だけが即座に切り替わります。

## 難易度（10段階）

レベルごとにレイアウト・ブロック耐久・破壊不能ブロック・ボール速度係数・バー幅が変わります。

| Lv | 名前 | Lv | 名前 |
| --- | --- | --- | --- |
| 1 | ならし運動 | 6 | 階段 |
| 2 | 市松 | 7 | アーチ |
| 3 | ピラミッド | 8 | 支柱 |
| 4 | 二重の壁 | 9 | 核 |
| 5 | ダイヤモンド | 10 | 要塞 |

レイアウトは `LEVELS` の `rows` にアスキーアートで定義しています。
`.` 空き／`1`〜`3` 耐久／`#` 破壊不能。1行8文字で、行を足せばそのまま段が増えます。

## ステージの進行

クリア時もゲームオーバー時も、5秒のカウントダウン後に自動で続きが始まります。

- **Lv1〜9 をクリア** → 次のレベルへ。ポイント・うんどう時間・のこり残機をすべて引き継ぎます
- **ゲームオーバー** → 同じレベルをやり直し。ポイントとうんどう時間は引き継ぎ、のこりだけ 5 に戻ります
- **Lv10 クリア／中断画面から「やめて記録する」** → 自動継続しません

カウント中も「いますぐ進む（再開する）」「はじめから」「メニューにもどる」は操作でき、
押した時点でカウントは止まります。

## 記録

プレイ日時・うんどう時間・ポイント・到達レベルを localStorage に保存し、**ポイント順の上位5件**を
自動登録します。1回のプレイ（セッション）につき1件だけで、途中のステージクリアで件数が増えることは
ありません。メニューの「記録を消す」で消去できます。

## 実装メモ

### GPU の使い方

| 処理 | 実装 |
| --- | --- |
| ゲーム描画 | WebGL2 のバッチレンダラ。矩形・角丸矩形・円・ハロー・ビネットを1本のシェーダで描き、1フレーム1ドローコール。`shadowBlur` のような CPU 描画は使っていません |
| 動作検出 | 映像を 64×48 に縮小してテクスチャ化し、前フレームとの輝度差をフラグメントシェーダで計算。CPU へ読み戻すのは下部 64×15 px（約1KB相当）だけです |
| カメラ映像の加工 | CSS フィルタ（blur・彩度・明度）でGPU合成。**検出には影響しません**（検出は `<video>` の生フレームを直接テクスチャ化するため） |

WebGL2 が使えない端末では、Canvas 2D 描画と CPU フレーム差分に自動でフォールバックします。
現在どちらで動いているかはメニュー最下部に表示されます。

### ボールの視認性

カメラ映像の CSS フィルタに加え、描画側で暗幕（設定で 0〜85% 可変）とビネットを重ね、
ボールには軌跡・ハロー・暗い縁取りを付けています。認識範囲や検出感度は一切変えていません。

### 音

すべて Web Audio でリアルタイム合成しており、音源ファイルは持っていません（オフラインでも鳴ります）。

- **BGM**：128BPM・8セクション64小節（約2分）のループ。
  イントロ→Aメロ→Bメロ→サビ→間奏→Bメロ→サビ→アウトロ。キック連動のサイドチェインとディレイ付き。
  構成は `SONG`、コード進行は `CHORD_ROOTS` / `CHORD_NOTES`、サビの旋律は `CHORUS_MEL` で定義しています。
  16分音符きざみのスケジューラ（先読み120ms・25ms間隔）なのでタイミングは安定します。
  ステージをまたいでも途切れず、メニューに戻ったときだけ先頭に巻き戻ります。
- **効果音**：パドル／ブロックヒット／破壊（破裂音）／破壊不能ブロック／ハート取得／ミス／クリア／ゲームオーバー。

### プライバシー

カメラ映像は端末内でのみ処理し、外部へ送信しません。サーバ通信もありません。
記録はブラウザの localStorage に保存されるだけなので、端末やブラウザを変えると引き継がれません。

### 調整しやすい場所

| 変えたいもの | 場所 |
| --- | --- |
| ステージ構成 | `LEVELS` |
| 速さの3段階 | `SPEEDS`（`m` が実速度、表示は N を1.00とした相対値） |
| 検出感度・検出範囲 | `DIFF_THRESHOLD` / `MOTION_MIN` / `MREGION` |
| 自動継続の秒数 | `endGame()` 内の `let left = 5` |
| 残機の初期値・ハートの出現率 | `startLevel()` の `G.lives` / `LEVELS[].drop` |

### キャッシュの更新

内容を差し替えたら `sw.js` の `CACHE`（現在 `knee-up-breakout-v2`）の版数を上げてください。
上げないと、インストール済み端末に古いファイルが残り続けます。
